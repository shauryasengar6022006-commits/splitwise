Reverse Engineering Architecture Diff

Standard Splitwise Database Schema vs. Our Predictive Staging Engine

Standard Splitwise Engine

  • • Strict ACID Mutations: Every interaction writes to persistent SQL tables (`expenses`, `debts`).
  • • No Staging Sandbox: Creating drafts triggers push notifications and taints live balances.
  • • Reactive Only: Cannot model "What if 2 people drop out?" without altering ledger history.

What-If Simulation Sandbox

  • • In-Memory Simulation: Pure state tree recalculated client-side with zero network noise.
  • • Zero Side-Effects: Headcounts and per-activity exclusions test budgets safely.
  • • Single Push Commit: Compiles winning plan to Splitwise's POST /create_expense format.
